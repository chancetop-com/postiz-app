# 将官方 Postiz v2.26.0 合入定制版并保留商户流程

Status: ready-for-agent
Created: 2026-11-20

## Problem Statement

商户从父应用的 iframe 进入 Postiz，在同一商户共享账户下管理渠道和排程。升级至 v2.26.0 后，他们需要继续使用原有账户、渠道和在途任务。新版还提供两个可能改变组织归属的入口。已有用户接受邀请时，要以邀请中的角色加入目标组织。收件人打开公开渠道链接时，即使浏览器正在使用另一个组织，也要把渠道绑定到签发链接的组织。

上次升级以 squash 合入 v2.25.3，Git 的共同祖先早于实际已吸收的版本。维护者需要准确识别这次新增了什么、哪些冲突涉及既有业务，以及候选版本是否能在当前部署配置下接续运行。

## Solution

从当前定制版制作本地候选版本，完整合入固定的 v2.26.0，保留上游提交历史。普通登录接入组织邀请，公开 API 和 MCP 接入按平台签发的 Connect Link。商户 SSO、标签页会话、找回密码、仪表盘六项渠道入口、品牌和既有排程沿用已确认的契约。

交付物为候选分支与最终提交、按业务流程取得的验收记录，以及分别对照升级前定制版和官方 v2.26.0 的差异报告。实施者从真实入口验证每条流程，直到能核对成员、渠道、帖子或平台发送结果。

## User Stories

1. 作为首次进入的商户，我希望从父应用直接进入新建的商户共享账户和组织，以便开始管理内容。
2. 作为已有商户，我希望再次兑换 SSO code 时回到原账户及其可用组织，以便继续管理原来的渠道和排程。
3. 作为同时使用两个组织的成员，我希望两个标签页各自保留身份、所选组织和代入状态，以便刷新、上传或切换组织时操作仍归于正确的组织。
4. 作为独立窗口用户，我希望邮箱注册、激活、密码和标准 OAuth 登录继续可用，以便自行进入 Postiz。
5. 作为受邀用户，我希望从同一条邀请链接使用密码、标准 OAuth 或已有会话接受邀请，以便在当前标签页以指定角色进入目标组织。
6. 作为组织管理员，我希望重复邀请只对应一条成员关系，失效邀请不能改变组织归属，以便成员名单和角色可信。
7. 作为找回密码的用户，我希望升级前收到且仍有效的链接能继续改密，原有正常登录也能继续使用，以便完成升级时正在进行的操作。
8. 作为账户持有人，我希望只有登录凭据能建立会话，重置链接只在有效期内用于改密，以便找回密码与登录各自有清楚的权限边界。
9. 作为管理员，我希望仍能开始和结束代入，以便按已有权限协助用户并回到原身份。
10. 作为商户，我希望仪表盘上的每个添加入口都提供约定的六种渠道，包括两种独立的 Instagram 接入方式，以便选对授权流程。
11. 作为嵌入页面的使用者，我希望在弹窗授权并完成必要的单账号选择后，原页面能刷新绑定结果，以便接着编辑帖子。
12. 作为独立窗口用户，我希望能在当前窗口添加或重连普通 OAuth 渠道，也能继续管理既有的其他渠道，以便恢复发布。
13. 作为组织的 API 或 MCP 使用者，我希望为上游支持的平台签发公开链接，包括仪表盘六项以外的适用平台，以便邀请渠道所有者授权。
14. 作为链接收件人，我希望匿名打开页面时看到定制 Logo、指定平台、权限说明和继续按钮，以便先确认用途，再决定是否前往平台。
15. 作为链接收件人，我希望取消后可以在链接有效期内重新发起授权，完成后可返回原站点，以便从中断处继续业务。
16. 作为正在使用组织 B 的收件人，我希望给组织 A 授权后，绑定只出现在 A，原标签页仍处于 B，以便两个组织的资源和身份各自独立。
17. 作为多渠道内容编辑，我希望保存草稿、立即发布、改期或删除只作用于本组织勾选的渠道帖子，以便同批其他帖子按原计划处理。
18. 作为商户，我希望桌面及移动端保留品牌、主题和约定的可见入口，以便继续使用媒体导入、编辑、上传、日历和分析。
19. 作为预览收件人，我希望能直接查看有效的公开内容并看到无效内容的既有提示，以便无需登录即可审阅帖子。
20. 作为商户，我希望旧渠道凭证继续支持刷新、重连和发布，核心流程在可选服务缺失时仍可用，以便沿用现有部署。
21. 作为有待发帖子的商户，我希望原定时区、发布时间、延迟评论和重复任务能跨升级接续，以便平台收到预期数量的发布请求。
22. 作为运维人员，我希望能在旧数据样本上核对启动同步、任务消费和故障恢复，以便了解升级过程中哪些步骤会阻塞服务或使发送结果待核实。
23. 作为维护者，我希望分别审阅升级带来的用户可见变化和相对官方版保留的差异，以便判断候选版本是否可交付，并在之后决定何时 squash。

## Implementation Decisions

| 比较角色 | 固定提交 | 实施用途 |
| --- | --- | --- |
| 官方 v2.25.3 | `a5affe62c74e39c1e7ac960d50d8418b807d532c` | 上一次已吸收的内容基准。分别与目标和当前定制版比较，识别上游增量和本地定制。 |
| 当前定制版 | `838843077adfa0fbffb58ecef82c9324412533aa` | 候选分支的产品起点。与候选结果比较，说明本次实际改动。 |
| 官方 v2.26.0 | `132859f32d854830ce44b509da87409c3ec10a77` | 完整合入此修订。与候选结果比较，核对每项保留或新增的适配。 |

- **合并历史。** 在本地专用分支保留定制起点和目标上游的祖先关系。本次上游增量为 152 个提交、130 个路径。双方共同修改 17 个路径，其中 8 个在显式内容基准下产生文本冲突。按完整流程解决冲突并核对自动合并项。只有无法同时保留已定行为的业务取舍才带实证交用户决定。[版本与冲突对照](assets/release-delta.md)
- **商户 SSO 与会话。** 保留父应用既有 URL、消息及完整兑换端点，以商户身份创建或复用商户共享账户，沿用原默认组织选择与成员有效性规则。`auth`、`showorg`、`impersonate` 经响应头进入当前标签页的 sessionStorage，后续请求携带相应头。保留 CORS 暴露、既有 Cookie 兼容读取、退出及 401 行为。标准 OAuth 登录继续验证绑定 provider、state 和时效的证明，登录回调与渠道绑定各走原流程。
- **组织邀请。** 接受邀请从邀请链接开始。服务端校验签名邀请和接受者身份，按邀请的组织及角色新增成员。新增成功后通过 `showorg` 更新接受邀请的标签页。已有成员重复点击时沿用既有成员关系，过期或无效邀请保持原组织归属。未激活账户继续遵循激活流程，无邀请时按原登录方式选择组织。
- **密码重置。** v2.26.0 没有等效的修复，保留定制版的独立签名、用途校验及 20 分钟有效期，到期即拒绝。仍在原有效期内的历史格式链接可用于改密，无效提交保留原密码。普通认证和查询代入前管理员身份均使用现有严格会话校验，既有有效登录继续工作。[重置令牌决策](issues/02-reset-token.md#answer)
- **仪表盘和公开链接。** 所有仪表盘添加列表只展示 `youtube`、`linkedin`、`tiktok`、`facebook`、`instagram`、`instagram-standalone`。保留其他 provider 注册、API 和存量绑定。公开 API 与 MCP 均按官方可签发条件选择平台。链接固定签发组织和单一平台，一小时内可重试。打开页面只显示定制 Logo、默认浅色、平台图标、权限说明及授权操作。点击继续时再核对组织与配额并发起平台授权。
- **授权回调。** 公开链接的绑定和二步保存均归于签发组织。匿名访问可直接完成，已登录收件人的原会话保留。成功或失败返回自定义地址时保留已有查询参数。无自定义地址时匿名者在当前页看到结果，已登录者沿用日历去向。仪表盘 iframe 添加继续由弹窗 relay 传递会话，需要单选时保存完成再通知原页刷新并关闭。独立窗口普通 OAuth 添加与重连沿用当前窗口导航。
- **界面与帖子。** 保留主布局 Logo、默认浅色和深色切换、桌面及移动导航隐藏项、隐藏的删除账户和永久交换身份入口、媒体工具可见范围、公开预览回退及可选服务降级。接入兼容的注册归因、平台图标、扩展渠道重连和账单权限反馈。多渠道编辑按所选帖子与所属组织执行保存、发布、改期和删除。
- **启动与存量数据。** 沿用现有部署配置，从最终根源码生成 K8s 构建上下文，保留 nginx、PM2 和单镜像内前端、API、worker 的运行形态。根镜像与专用镜像均在每次启动时执行官方数据库同步，成功才启动应用，失败时非零退出。该版新增五个普通索引，分别属于 Post（两个）、Notifications、User 和 Errors。旧身份、渠道、媒体引用、帖子状态和排程时间沿用原数据。
- **渠道凭证。** 默认沿用当前配置读写旧凭证。加密是可选能力，仅作用于渠道访问令牌与刷新令牌。若另行评估启用，API 和所有 worker 先配置同一密钥，验证能读明文与密文，期间继续写明文。各进程均验证通过后再开启密文写入。历史回填单独触发，支持混合记录和并发刷新。恢复后仍须能解密既有记录。[凭证、索引与任务的核查结果](assets/upgrade-data.md)
- **Temporal。** 保留旧 workflow 和 activity 的名称、载荷、既有队列、兼容队列 worker 及定制的刷新 activity 注册。V101/V102 旧执行继续按原协议运行，V112 保留 pending、check、finalize 及超时结果未知的处理。保留上游补偿扫描对当前帖子状态的复查。批量刷新中单个 provider 刷新失败后继续处理其余渠道，首次标记需要重连时才通知。

## Testing Decisions

用户已确认以**隔离应用栈中的浏览器和公开 HTTP 入口**作为主要测试边界，外部父应用兑换及平台 OAuth、发送服务使用可控替身。另从实际容器启动验证数据库和媒体，从 Temporal 历史回放与真实 worker 消费验证在途任务。测试断言页面、持久化关系、请求结果和平台调用次数。现有的商户 SSO、OAuth 会话往返、渠道弹窗与二步绑定、密码重置、启动同步及排程接续套件可直接扩展。[确定新入口与历史业务流程的合并验收](issues/04-flow-acceptance.md#answer)

| 入口与场景 | 候选版本的必验结果 |
| --- | --- |
| 父应用 iframe 与独立窗口 | 禁用第三方 Cookie，实际走首次及再次兑换、失败、刷新、两个标签页各选组织、管理员代入与退出。核对账户复用、会话请求头、各标签页当前身份，以及上传和 401 后的既有行为。独立窗口跑注册、激活和标准 OAuth 登录。 |
| 实际组织邀请链接 | 分别以密码、普通 OAuth、仅有 sessionStorage 的已有会话接受。核对新增成员的组织、角色和数量，确认接受邀请的标签页收到并使用目标组织，另一标签页保留原组织。覆盖已是成员、无效或过期邀请、未激活账户及无邀请。 |
| API 和 MCP 签发的公开 Connect Link | 两个入口各覆盖六项内和六项外的适用平台。用 A 的链接分别走匿名、A 成员、当前使用 B 的收件人。先看同意页，再点击、取消、重试、完成必要的二步单选并查询 A/B 的绑定。到期被拒，取消不新增绑定，二步失败可重试，B 的原标签页仍在 B。核对无返回地址和带原查询参数的返回地址。 |
| 仪表盘渠道绑定 | 枚举所有添加列表。对六项分别走 iframe 弹窗和独立窗口流程，核对 relay、保存结果、回传、刷新及重连。YouTube、Facebook Page、Instagram（Facebook Business）完成单选后再核对实际绑定。拒绝、取消、弹窗异常和保存失败均以渠道实际状态定结果。 |
| 找回密码与登录 | 用历史和现行两种格式覆盖有效期内、到期瞬间及到期后。核对合法重置能改密、无效提交不改密。请求头和兼容 Cookie 两条入口均拒绝将重置凭据用于登录或原管理员身份查询，升级前的有效登录继续通过。 |
| 多渠道帖子与界面 | 用同批勾选与未勾选的帖子，以及另一个组织的帖子，逐项验证保存草稿、立即发布、改期、删除的影响范围。核对普通成员和管理员的账单反馈、主题及隐藏入口、有效和无效匿名预览。在缺可选服务时走日历、媒体、编辑、排程及分析，核对受保护 AI 请求的既有 503 和 MCP 启动失败时核心 API 可用。 |
| 旧数据库与实际镜像 | 对隔离 PostgreSQL 15 旧库实跑两种镜像入口、重复启动和同步失败。核对五个索引的定义及列序、建索引耗时与锁等待、原行主键与原列摘要、渠道及成员关系、帖子时区及媒体引用。用实际卷读旧媒体、上传新媒体并在重启后读取。 |
| 历史渠道与可选加密 | 默认配置下，用合成的旧 Instagram、Skool、六项渠道及历史其他渠道样本走读取、刷新、重连和发布。核对组织、渠道 ID、账号及页面关联、失败通知次数与并发刷新结果。若评估加密，再验证两类进程的混合格式读写、错密钥及恢复、并发回填不覆盖新凭证、静止样本重复回填零变更零失败。 |
| 在途任务与故障 | 用候选 bundle 回放旧历史，再让隔离 worker 接手续跑睡眠排程、重复子任务、延迟评论、积压刷新和邮件。核对原队列、workflow 与业务 ID、数据库状态，以及平台替身收到的次数。覆盖扫描期间取消或改期、平台已接受而写回失败、finalize 超时。记录结果未知，按平台账目核对重复发送和恢复结果。 |
| 构建、检查与交付 | 从根目录用 pnpm 跑完整测试、前端/API/orchestrator 类型检查、lint 和构建，记录候选提交、命令及结果。核对生成的 K8s 上下文与根源码，实跑候选镜像和三个进程。在报告中逐项列出相对旧定制版的变化、相对官方 tag 的差异路径及保留理由，并关联对应的验收证据。 |

真实父应用联调、Safari 跨站会话与弹窗、六种渠道各自的真实授权分别记录结果、缺失条件及影响。全部本地必验项实际通过且仅缺外部条件时，交付状态可写为「代码合并完成、本地验收通过、外部验证待补」。观察到的失败按失败记录，本地设施缺失按本地未验记录。

## Out of Scope

线上发布镜像、部署、生产数据同步或回填、变更父应用协议和默认开启凭证加密均留待另行决定。此次升级保持固定 tag 范围。Squash 的时机由用户在实现完成后指定。
