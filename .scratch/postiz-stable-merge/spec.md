# 完整合并 Postiz v2.25.3 并保留现有定制流程

## Problem Statement

商户通过父应用内嵌的 Postiz 管理社交内容，需要继续免二次登录进入商户共享账户，连接既定渠道，使用媒体、日历、编辑、排程和分析。当前 fork 已在两个定制提交中实现商户 SSO、iframe 会话与渠道弹窗、品牌界面、入口隐藏、可选服务降级以及专用构建运行方式，但与锁定官方稳定版已有较大差距。

只复制部分 provider 或挑选提交，不能完成官方稳定版升级；直接采用官方文件又可能丢失定制流程。文本自动合并也不足以证明兼容：已发现自动合并后的导入缺失，以及构建目录仍保留旧源码等问题。存量身份、渠道凭据、帖子、媒体和长期 Temporal 任务也需要在新代码下继续工作。

维护者需要一份完整、可执行、可验证的合并契约，明确保留什么、接受哪些兼容上游更新、如何证明本地结果，以及最终相对升级前 fork 和官方上游分别有哪些实际变化。上线时机由用户最后另行决定，不能让本地构建或验证隐式触发发布部署。

## Solution

在本地专用分支中，将已锁定的官方稳定版 **v2.25.3** 的完整历史及实际变化合入当前 fork，逐项保留两个定制提交建立的完整使用流程、业务结果和明确的界面范围。兼容的上游更新直接纳入；常规技术冲突自行适配。只有证实无法保留既定流程、必须改变体验或范围的问题，才携带具体证据交用户决定。

核心流程为：父应用进入 → 商户 SSO 免二次登录 → 正确商户共享账户与组织 → 六个既定添加入口 → iframe 弹窗携带会话 → 外部授权与必要的单账号选择 → 回传刷新并关闭 → 媒体、编辑、排程、发布与分析。普通窗口登录、添加渠道和重连也保持各自既有契约。

保留单镜像、nginx 和 PM2 三进程的运行方式，从最终根源码生成完整构建输入。容器每次启动先执行官方数据库同步，成功后启动应用；用隔离旧数据、模拟外部服务、Temporal 历史回放与任务接续证明兼容。最终交付本地分支、最终修订、验证记录，以及覆盖全部差异路径的双向改动报告。

## Implementation Decisions

### 版本、范围与合并原则

- **固定引用**：规划起点及本次只读核对的 HEAD 为 `501e87dbfb2ca6e44662baec308afa468a922b38`；两个定制提交为 `f042c177c1a378edacd54790614bdd9f709a2480` 与 `6fdf7cb53543fa28a470ad63e7619e8b98bcee43`；后者为产品行为基准。共同基线为 `0b554e684483932d394e703208fe21648e7acd6f`。目标固定为 v2.25.3 / `a5affe62c74e39c1e7ac960d50d8418b807d532c`，不重新追逐最新版本。执行前记录实际起点与工作区状态，保留已有工作。
- **真实 merge**：在本地 `codex/` 前缀专用分支实施；执行起点、两个定制提交及目标上游均须成为最终结果祖先。将目标完整可达历史和实际变化纳入，不能以文件复制、选择性 cherry-pick 或空的 ours merge 代替。已核对共同基线后目标包含 999 个上游提交；稳定目标之后的主线不在本次范围。
- **逐项追踪**：已有清单覆盖两个定制提交归并后的 863 个净变更路径。按行为及来源追踪根源码、静态资产、文档、构建配置、对应副本与独有配置；相同副本可归组，但不能遗漏路径或把副本数当成独立功能数。
- **保留完整流程**：保留业务结果和明确界面范围，接受不破坏这些目标的上游实现及异常处理更新，不要求旧代码逐行或所有异常分支完全相同。不能用旧整文件覆盖新实现来回避适配，也不能把无文本冲突当成行为证明。
- **具体冲突处理**：先尝试保持契约的技术适配；只有确实无法兼容时，提供原行为、上游变化、受影响入口、复现证据、已尝试办法及方案影响，交用户评估。未获变更决定前不得静默改变产品契约。
- **模块边界**：改动围绕认证与共享请求、渠道连接与回调、主布局与媒体、可选服务初始化、源码打包与运行、Prisma 数据结构以及 Temporal workflow/activity。保持既有 Controller → Service → Repository 分层，必要时经过 Manager；不借升级作全局重构。前端沿用现有组件、Tailwind 3 主题及独立 SWR hook 与 useFetch 方式，不安装第三方成套 UI 组件，不使用废弃颜色变量。

### Postiz 登录、商户共享账户与会话

- **父应用入口**：保留 `/auth/sso?token` 转接、`/sso?auth_code` 与 SSO 页既有 `SSO_TOKEN` 消息入口。URL code 优先、监听时机和来源配置保持当前契约；不新增持续监听切商户或父页成功/失败通知协议。
- **兑换与开户**：SSO_SERVER_URL 是完整兑换端点，POST 请求携带 auth_code，响应 merchant_id/merchant_name 映射到商户身份；不自动拼接路径，不增加独立开户接口或 needsCreation 分支。继续通过 GENERIC + merchantId 查找并复用商户共享账户，首次创建用户和组织，初始组织角色保留 SUPERADMIN，不能与全局管理员混淆。
- **组织选择**：保留既有查询、orgs[0] 选择、成员有效性检查、回退及手动切换；已有用户缺组织时不自动补建。不因上游订阅组织优先等变化重排归属、不重绑身份或引入命名空间迁移。
- **会话存储**：保留 sessionStorage 中 auth/showorg/impersonate、非空响应头覆盖、cookie 兼容与优先级，以及各标签页分别保存状态。SSO 开始或失败时不新增旧会话清空；不新增全标签同步、会话有效期或来源校验策略。渠道弹窗使用既定专用传递流程。
- **页面与普通登录**：保留邮箱登录、注册、激活、标准 OAuth 登录和独立窗口访问。保留客户端用户检查与 proxy 分工，不恢复阻断 iframe 的 cookie 页面门禁。兼容上游登录 OAuth state 往返校验，不通过删掉校验解决问题。
- **既有分支**：退出、401、网络错误、管理员代入、上传、Copilot 与预览按各自基线比较；不统一改写。停止代入未清 sessionStorage、旧 cookie/组织残留和部分旁路请求头不齐属于已知基线缺口，记录其影响，不借升级实施已撤回或未约定的修复。
- **两项账户功能**：普通账户、商户账户、管理员及桌面/移动所有界面均隐藏删除账户与永久交换登录身份入口；保留其源码、路由与接口行为，不新增后端拒绝逻辑。现有管理员代入入口和行为继续保留，不能把永久凭据交换与代入混称。

### 六项渠道与完整授权回传

| 精确 identifier | 可见添加入口 |
| --- | --- |
| youtube | YouTube |
| linkedin | LinkedIn 个人账号 |
| tiktok | 现有 TikTok 接入 |
| facebook | Facebook Page |
| instagram | Instagram (Facebook Business) |
| instagram-standalone | Instagram (Standalone) |

- 所有社交、文章及新版添加/选择入口均遵守上述白名单。不能按显示名称或平台家族放入 linkedin-page、tiktok-business、tumblr 等其它 provider。保留其它 provider 注册、代码、接口及存量绑定的管理和发布能力，不新增后端禁用。
- iframe 添加保留 popup → URL hash 会话 → channel-relay 写入 popup sessionStorage → 外部 OAuth → callback → opener 刷新/关闭的链路，传递 auth/showorg/impersonate。普通窗口添加及六项普通 OAuth 重连继续当前窗口导航。
- 需要中间选择的 YouTube、Facebook Page、Instagram (Facebook Business) 保留单选和保存步骤，不扩展成批量绑定，也不在保存前通知关闭。

## Testing Decisions

### 测试边界与既有确认

沿用验收交接票中用户“都按建议”确认的本地验收边界与交付方式，不重新提出产品取舍。主要测试入口是**真实浏览器操作与公开 HTTP API 驱动的隔离应用栈**，复用现有页面、认证、渠道和帖子边界；仅在父应用兑换、外部 OAuth/平台调用等系统边界设置可控替身。尽量用同一套旧数据和运行环境覆盖连续流程，不为每个内部 helper 新增测试接口。

另保留两个无法由页面成功替代的验证边界：**实际容器启动和持久化生命周期**，以及 **Temporal 历史 replay 与 worker 执行**。它们证明数据库同步/失败阻断、产物运行和工作流历史兼容，沿用已确认的要求；不为了追求单一测试入口而删去这些证据。

好的测试从用户操作、公开请求或真实启动事件进入，断言可见结果、身份与组织归属、持久化变化、平台替身调用及任务状态。除必要的协议顺序、调用次数、数据保留核对外，不绑定私有函数、组件结构或实现调用顺序。浏览器测试不能完全 mock 掉内部 API 后声称验证了整条流程，replay 也不能代替平台副作用验证。

### 现有基础与需补齐的部分

- 当前根包声明 Jest、Nest testing、Testing Library 等依赖；根 Jest 配置依赖未直接声明的 Nx Jest 集成，且本次核对未发现已跟踪的自动化 test/spec 用例。因此没有现成的同类完整回归套件可直接声称复用，需在执行阶段落实可运行入口与有意义用例。
- 既有 SSO 手工测试页与 mock 可作为父页/兑换替身的起点，但消息名和兑换、一次性 code、失败及回传覆盖存在缺口，须按真实契约适配，不能直接当作完整授权验收工具。
- 优先复用现有 HTTP/controller 边界、workflow 导出、旧版生成的历史 fixture 和真实镜像入口。新增测试基础设施只服务上述高层契约，不在产品中散布测试专用接口；具体 runner 配置属于执行技术选择。
- 构建以根目录 `pnpm run build` 为入口；类型检查分别覆盖前端、API、orchestrator，准备 Next 生成类型；lint 从根目录运行，覆盖三应用与共享库。根目前没有 lint/typecheck script，候选命令与配置须在执行时落实。现有 Jest 入口也须修复并产生非零有效用例，不接受空测试成功。

所有平台调用由隔离替身接收，不让历史任务样本触发真实发布。测试 fixture 只含合成身份、凭据和历史；真实 Secret、备份、history payload 不进入仓库资产。

### 验收门槛与外部条件

- 全部本地必验项实际通过后，才能交付为“代码合并完成、本地验收通过”。已知影响约定流程或升级安全的失败阻止相应验收；分别记录升级前基线失败、合并新增失败与缺条件未验证，基线分类不是自动豁免。
- 缺工具、依赖或本地测试基础设施不能归入真实账号等外部条件缺口，也不能以 shell 语法、静态审阅、旧镜像或零用例代替运行通过。
- 六渠道真实 OAuth 分别检查同意页、重定向、拒绝/取消、选择保存、绑定状态和重连；真实父应用、真实 origin、Safari 等浏览器 cookie/popup 行为须有实际外部结果。mock 不证明平台配置、权限或真实跨站可用。
- 本地必验全部通过、仅缺真实账号/父应用联调等外部条件时，允许交付为“代码合并完成、本地验收通过、外部验证待补”。逐项写明缺少条件、步骤、影响、结果位置与待安排执行人，不宣称全部端到端验收或可以上线。实际失败不能改写成缺条件。
- 真实 Pod/imageID、线上 schema 漂移、在途任务、队列历史、备份恢复与停写窗口归未来上线核验，不新增为本次本地验收的前置条件，也不得声称已验证。
