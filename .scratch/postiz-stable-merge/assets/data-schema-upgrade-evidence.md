## 已证实的总览

- 完整 schema 对比为 **48 → 88 models、10 → 11 enums**：40 个新增 model（37 个 `mastra_*`、Clipping、ClippingClip、OAuthSelfHostedAuthorization），一个新增 CreationMethod enum；没有删除 model、已有字段或已有 enum 值。下方附录按字段列出完整增量。
- 用户、组织、成员、渠道、帖子、媒体的主键和已有关系标识未更换。User 的唯一约束仍是 `[email, providerName]`，没有新增 `[providerId, providerName]` 唯一约束；UserOrganization 仍唯一 `[userId, organizationId]`；Integration 仍唯一 `[organizationId, internalId]`。不能因此假设真实库没有重复 GENERIC 身份或漂移。
- 核心表新增的非空列均有默认值：Media.status=`ready`、Subscription.provider=`stripe`、Post.creationMethod=`UNKNOWN`、OAuthApp.dynamic=`false`。其它核心新标量为 nullable；Comments.userId、OAuthApp.organizationId/clientSecret 放宽为 nullable。
- 新增约束风险不是身份重映射：`mastra_ai_spans` 新增复合主键 `[traceId,spanId]`，并且仍有 `@@ignore`。**没有运行 Prisma SQL 生成或应用，所以不能据 `@@ignore` 推断这个 DDL 一定跳过。** 在隔离测试副本检查同键重复和官方 db push 的实际结果；必要时可生成 SQL 辅助审阅约束影响，不将 SQL 作为独立升级执行入口；不自动删重复来通过。
- 原有索引/唯一约束没有从 schema 删除；Mastra 多处在保留 `public_*` 索引的同时增加相同列的另一名称索引。nullable 关系可能导致生成的外键动作发生变化，需检查实际 SQL，不能只按字段增量宣称无约束变化。

## 技术建议，尚非执行结果

1. 按用户最终确定的[官方数据库升级方式](../issues/08-data-temporal-upgrade.md#已明确的官方数据库升级方式)，使用最终合并 schema 和锁定 Prisma 6.5.0 的 `pnpm run prisma-db-push`：每次容器启动先同步数据库结构，成功后再启动应用进程，定制 k8s 镜像也接入这一顺序；同步失败阻断启动。命令不含 `--accept-data-loss`，不使用 reset，不另建独立升级脚本或版本化迁移体系。Prisma generate 仍仅生成客户端，镜像构建不连接数据库。必要时生成 SQL 只作辅助审阅，不作为另一执行入口。本次 C→S 清单是兼容验证输入，不代表最终 schema 或官方同步已经通过。
2. 在隔离 PostgreSQL 15 样本验证官方启动同步、失败阻断及重复启动，再比对同步前后行数、所有主键集合、组织成员关系、原列摘要、媒体路径及文件哈希、帖子状态/日期/group/parent/release 字段；token/密码只在受控程序内比较，不输出值。构造商户首次/复用、多组织、旧 GENERIC/OAuth 混用、软删和缺关系等[SSO 身份与整站鉴权契约中的场景](../issues/03-sso-auth-contract.md#验收场景)。
3. 单独检查 mastra_ai_spans 的复合键重复、已有表/索引 drift，以及新 SDK 初始化是否再写 schema。遇重复或陌生表停止该步骤并保留原数据；不能把删除 AI 表/重复 trace 当成默认可接受损失。
4. rootInternalId、旧 JWT、Instagram 单 token、旧 path 和 browser timezone 是具体兼容样本。优先在应用端双读/兼容适配；没有证明必须做整表业务回填。官方 schema 同步的默认填充值不等于商户身份迁移。
5. 逆向 schema 不是镜像回退的等价物：S 可能写 APPLE enum、新 nullable Comments/OAuth 字段、新 credential 格式、新 media path 或新业务记录。旧应用能否在扩展 schema 上运行须实测；不能为回退 drop 新列/表以求形状相同。数据库、uploads、Temporal 的一致恢复和暂停窗口由[数据与 Temporal 升级票](../issues/08-data-temporal-upgrade.md)汇总。

所有真实库 drift、数据量、唯一键冲突、文件可达、凭证可用、旧 worker 与新 schema 共存和恢复时间仍未验证；这些是未来上线前需要的运行证据，不是本轮要求连接生产的理由。
