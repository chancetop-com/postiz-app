# 11: 用历史渠道凭证刷新、重连并发布

**What to build:** 沿用当前部署配置，商户升级前已有的渠道仍能管理、刷新、重连和发布。平台替身收到的账号、页面和渠道身份与原绑定一致。

**Blocked by:** [01 合入固定版本并跑通候选版](01-merge-and-run-candidate.md)

**Status:** ready-for-agent

**Source:** [升级规格](../../postiz-v2.26.0-wayfinder/spec.md) · [默认配置与可选加密](../../postiz-v2.26.0-wayfinder/assets/upgrade-data.md)

- [ ] 用合成凭证覆盖旧 Instagram 单令牌及组合格式、旧 Skool 格式、仪表盘六项渠道及其他历史渠道。经页面或公开 API 读取、刷新、重连并发布，核对组织、渠道 ID、账号、页面、凭证有效期及平台替身结果。
- [ ] 验证批量刷新中某个 provider 失败后其余渠道继续处理，同一渠道首次标记需重连才通知。并发刷新时核对最终采用的有效凭证及后续发布。
- [ ] 默认配置下保留存量凭证和部署方式。核对多页面及同账号跨组织样本的实际关联，记录结果时使用合成样本标识。
- [ ] 条件验收仅在另行评估加密时执行。API 与所有 worker 用同一密钥先读明文与密文并继续写明文，再验证加密写入、空值、重启、错密钥及恢复。验证并发回填保留已刷新凭证，静止样本重跑零变更、零失败。
