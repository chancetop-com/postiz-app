# 10: 让 URL 导入和后台生成媒体写入 Azure

Status: resolved
Blocked by: 06

**What to build:** 通过现有 URL 导入入口或后台生成功能添加媒体，得到保存在当前组织目录、可预览并用于排程的文件。

- [x] 公开 API 的 URL 导入沿用请求与响应，并保留原有远程来源校验、类型识别及流式大小限制。导入失败不登记文件。
- [x] 后台生成图片或视频时将任务所属组织传至写入点。媒体记录引用新对象的持久 Blob 源站地址，写入过程可在无上传盘时完成。
- [x] 本地替换远程来源、生成服务和存储端点，从导入入口及代表性的后台生成入口核对组织、返回结果和读回字节。共用写入路径沿用同一组断言。

以现有 R2 行为和测试为参照，在本地验证 Azure 的差异。真实环境配置与验证由环境负责人按手册执行。

[父规格](../spec.md) · [存储与 Blob 源站地址约定](02-environment-and-urls.md#answer)

## Answer

公开 API 和 MCP 的 URL 导入将鉴权得到的组织 ID 传给流式写入器。网页、MCP、Copilot 及第三方集成生成的媒体共用服务层写入和登记。视频任务把组织 ID 单独传给生成器，旁白 MP3 与最终 MP4 位于同一组织目录。渠道连接和选页时也使用渠道所属组织复制头像。

本地 `tests/azure-generated-media.test.ts` 的 7 项用例已通过。测试未配置上传盘，使用真实 Nest 路由、MCP 工具、视频活动、Azure SDK 及临时 HTTPS Blob 服务。远程素材和生成服务返回固定字节，数据库使用内存替身。

- 公开 API 导入按内容识别 PNG，保留鉴权组织与原有媒体记录。远端 404、内容不受支持、实际图片超过 10 MiB 时仍返回原有的 400 错误体；非 HTTPS 来源在请求校验时被拒绝。上述失败均无登记，也无已提交对象。
- 网页生图、第三方命名导入与 MCP 生图、导入均核对了各自的响应、组织和匿名读回字节。第三方显示名称与服务器生成的对象名可分别保存。
- 视频活动使用任务组织生成可匿名读取的 MP3，模拟渲染服务从该地址读取旁白。最终记录中的 MP4 和渠道头像也从 Blob 源站读回并核对类型与字节。dev 地址形式为 `https://<Blob 源站>/postiz/dev/<merchantId>/<文件名>`，无 SAS 查询参数。

另已通过公开 multipart 的 12 项回归（包含 1 GiB 视频的精确边界）、本地上传 13 项及渠道选页 11 项。真实 Azure 账户配置、dev Pod 和社媒实发由环境验收覆盖。

第三方命名导入复用公开 URL 导入的类型识别和逐字节大小限制。下载地址重定向后继续验证公开 HTTPS 来源。超限或拒绝时不登记媒体。
