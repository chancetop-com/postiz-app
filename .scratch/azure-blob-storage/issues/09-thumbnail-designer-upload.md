# 09: 让缩略图和设计器使用直传

Status: resolved
Blocked by: 07

**What to build:** 复用已接通的 Azure 直传流程，在视频编辑器中保存缩略图，在设计器中保存并选用作品。

- [x] 视频编辑器截取或选择封面后，调用方只得到可匿名读取的 Blob 源站地址，未新增媒体库记录。
- [x] 设计器保存后得到归属当前组织的媒体记录，能直接用于编辑中的帖子。确认重试仍返回同一记录。
- [x] 从两个界面各走一次本地上传，核对调用方实际消费的结果。上传或确认失败时不应用无效的封面或设计稿。

以现有 R2 行为和测试为参照，在本地验证 Azure 的差异。真实环境配置与验证由环境负责人按手册执行。

## Answer

视频编辑器可以选择本地图片、截取视频帧或沿用媒体库图片。本地图片和截帧以 `thumbnail` 用途直传，确认接口仅返回 `{ path }`。保存封面只更新原视频，媒体库已有图片则直接复用其地址。设计器导出的 PNG 以 `media` 用途直传，确认后把媒体记录的 ID 和持久地址交给当前帖子的附件字段。

本地 Chromium 使用现有编辑器，连接 Nest、PostgreSQL 和 HTTPS Blob 协议模拟服务。9 项回归覆盖所选 JPEG 的匿名读回与字节比对、实际视频 100 毫秒处的蓝色帧和时间戳、图库选图、Polotno 导出的 80 × 60 PNG 和帖子预览。视频信息保存失败后重试会复用已确认的封面地址，只申请一次上传授权。丢弃设计器首次确认响应后，同一上传标识再次返回同一条 `ready` 记录。两个编辑器均验证了 Blob 写入被拒和 Postiz 拒绝无效内容时保留编辑状态，原视频及媒体库记录不变。[浏览器回归](../../../tests/azure-editor-upload.test.ts)

真实 dev 的跨域写入和匿名读取由环境负责人按[部署手册](../dev-runbook.md)验收。
