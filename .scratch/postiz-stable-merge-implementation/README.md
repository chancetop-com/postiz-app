## 执行约束

- 以规格和决策票的最终 Answer 为准，历史评论中的撤回方案不得重新成为要求。每张票同时遵守本节和其自身验收条件。
- 固定目标为 v2.25.3 / `a5affe62c74e39c1e7ac960d50d8418b807d532c`。规划起点为 `501e87dbfb2ca6e44662baec308afa468a922b38`；执行前重新记录实际起点及工作区状态，保留已有工作。定制提交为 `f042c177c1a378edacd54790614bdd9f709a2480`、`6fdf7cb53543fa28a470ad63e7619e8b98bcee43`，后者是产品行为基准。
- 在本地 `codex/` 前缀专用分支完成真实 merge，纳入目标完整历史和实际变化，不用选择性复制、cherry-pick 或空的 ours merge 替代。02 交付可编译、可继续验收的合并候选；完整流程和最终候选通过由后续各票及 18 证明。
- 保留完整使用流程、业务结果和明确界面范围，接受兼容上游更新；常规技术冲突自行适配。只有确实不能维持已定流程时，才附原行为、上游变化、复现、已尝试办法及方案影响交用户决定。
- 遵循仓库分层、既有组件、Tailwind 3 主题、独立 SWR hook 和 useFetch 约定。仅使用 pnpm，lint 从根目录执行，不借升级做全局重构。
- 各票包含自身的有意义回归验证。优先从浏览器、公开 HTTP API、真实容器生命周期及 Temporal replay/worker 进入；只在外部系统边界设置替身，不新增产品测试专用接口，不以内部 API 全部被 mock 的浏览器检查证明完整流程。
- 数据、身份、凭据和历史 fixture 均使用隔离合成样本；平台调用只进入替身。敏感值在受控程序内比较，不写入日志或交付资产。每票记录实际命令、版本、场景、用例数、结果及证据位置，区分基线失败、新增失败和缺条件未验证。
- 维护两个定制提交全部 863 个净变更路径的追踪关系；副本可归组但不能漏路径。每票将所触及事项关联到最终实现、行为、验证结果及适配原因，18 汇总最终结果。
- 不自行发布镜像、推送代码、创建 PR、更新集群、迁移真实数据、读取真实 Secret 或重新启用 Build。发布和部署能力可以保留为明确的独立动作，但本地准备、构建和检查不得调用它们。是否上线由用户另行决定。
- 全部本地必验项实际通过才可宣布本地验收完成。工具缺失、空测试、静态检查或无 CI 运行不能冒充通过。真实父应用/OAuth 缺口可以单独报告；实际失败不能改写为缺外部条件。
